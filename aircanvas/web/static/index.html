BROWSER LIMITS

  • No OS cursor, global shortcuts or transparent desktop layer.
  • Camera needs a user gesture and localhost / HTTPS.
  • Background tabs may throttle camera processing.
  • Desktop build integrates those native features.
BROWSER SECURITY

Why some desktop features stop at the browser

A web page is sandboxed by design. These restrictions are real limits, not missing AirCanvas code.

  • Camera permission. getUserMedia requires localhost or HTTPS and an explicit click.
  • No transparent desktop overlay. A page cannot paint over other applications or become click-through.
  • No OS input. JavaScript cannot move the system cursor or inject global keyboard shortcuts.
  • Tab lifecycle. Background throttling can pause camera frames and recognition.

The PySide6 desktop build provides native mouse, system navigation and a transparent overlay using a separate consent gate. Both interfaces share the same gesture, drawing and tracking core.
