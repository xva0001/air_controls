# 測試與評估程序

本文件說明 AirCanvas 如何驗證，以及如何重現這些檢查。文件將**自動化測試**、**瀏覽器/執行階段測試**與**手動驗收測試**分開，讓評分者能專注於互動品質，而不只是單元測試。

---

## 1. 測試環境

| 項目 | 值 |
| --- | --- |
| 作業系統 | Windows 11（建置環境） |
| Python | 完整 52 項測試與最終相機路徑均使用**全局 3.15.1** |
| 桌面版 | PySide6 6.12.0，螢幕截圖使用 Qt 離屏 |
| 視覺 | MediaPipe Tasks 1.2.0、OpenCV 5.0.0（contrib、CSRT） |
| 網頁版 | FastAPI 0.162、Uvicorn 0.54、Chromium 156 |
| 顯示 | 1480×920 桌面/網頁，390×844 響應式 |
| 相機 | 機器有實體網路攝影機，但代理沙箱封鎖裝置存取；已用全局 Python 3.15.1 非沙箱驗證（MSMF 1280×720）。另使用模擬影像來源 + 真實手部影像 + 合成 MediaStream。 |
| 自動化測試套件 | 52 項測試，全部通過 |

測試用的設定檔與快取會重新導向至 `.cache/`，因此測試不會修改使用者真正的設定檔。

## 2. 自動化測試

### 2.1 指令

```powershell
# 最終相機路徑使用的全局 Python 3.15.1：
python -m pip install -r requirements-dev.txt
python -m pytest tests -q

# 或在乾淨的 venv 中：
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
```

請**勿**在受限沙箱中於儲存庫根目錄直接執行單純的 `pytest`，因為 pytest 的快取目錄會被套用限制性 ACL；`tests/` 是明確的測試路徑。`pyproject.toml` 也設定了 `testpaths = ["tests"]`。


### 2.3 靜態檢查

```powershell
ruff check aircanvas tests scripts run_desktop.py run_web.py
python -m compileall -q aircanvas scripts
Get-ChildItem aircanvas\web\static -Recurse -Filter *.js | ForEach-Object { node --check $_.FullName }
```

Ruff 其餘刻意保留的檢查結果僅限於：盡力而為的原生操作外層的廣泛例外防護、刻意使用 `except: pass` 的清理路徑，以及為相容 Python 3.10 而保留的 `str, Enum` 類別。這些都有文件說明，而非全面以忽略方式消音。

### 2.4 真實手部 MediaPipe 驗證

將一張公有領域風格的手部照片（`woman_hands.jpg`，開發期間下載，未重新散布）通過 `HandTracker` 處理：

- 21 個特徵點、單手、慣用手為 `Right`、分數 0.96。
- 手勢分類為 `open_palm`。
- 在 CPU、960×640 下，推論平均 **15.8 ms**、p95 **17.2 ms**。
- 首次模型初始化約 1.2 秒。

這驗證了 MediaPipe Tasks 路徑，且不依賴模擬特徵點產生器。

### 2.5 全局 Python 3.15.1 相容性

目前機器已成功以**全局** Python 3.15.1（PySide6 6.12.0、OpenCV 5.0.0、MediaPipe 1.2.0）執行桌面版。過程中找到並修正兩個環境專屬問題：

1. **Python 3.15 惰性匯入 + PySide6。** MediaPipe 的 `SerialDispatcher` 收到 `lazy_import` 物件而非 `ThreadPoolExecutor`，產生 `TypeError: 'lazy_import' object is not callable`。`aircanvas/gestures.py` 現在會在 MediaPipe 初始化前解析並固定實際的 `concurrent.futures` 類別。
2. **MSMF property 53。** 將 `CAP_PROP_OPEN_TIMEOUT_MSEC` 傳給 OpenCV 5.0 的 MSMF 後端會造成 `can't set property 53` 並開啟失敗。相機開啟器已不再傳遞這些參數；改為每個後端都必須實際讀到一張影格。

快速檢查（若相機被沙箱封鎖，請在一般 PowerShell 執行）：

```powershell
python scripts/smoke_global_python.py
python scripts/smoke_global_python.py --camera
```

本機非沙箱驗證：

- Python 3.15.1 / PySide6 6.12 / OpenCV 5.0 / MediaPipe 1.2。
- 相機透過 **MSMF** 以 1280×720 開啟。
- 4 秒處理 103 幀，**31.5 FPS**、**17.3 ms** 辨識時間，無 `recognition_error`。

### 2.6 瀏覽器執行階段驗證

由於建置沙箱會封鎖瀏覽器子行程管道，螢幕截圖與執行階段檢查是透過 Chrome DevTools Protocol 驅動：

- 頁面載入時沒有 JavaScript 例外（`window.__errors` 為空）。
- 以 `seek=6.0` 啟動示範可到達追蹤標記。
- 螢幕示範會產生修正後的圓形 + 自由手繪線（2 筆）。
- 390×844 的響應式版面。
- 瀏覽器相機流程透過注入合成 `MediaStream` 驗證：
  - `camera.status` 變成 `browser live`；
  - 伺服器收到 640×480 影格；
  - 合成影像中沒有手部時，處理速度約 11.9 FPS；
  - 沒有頁面錯誤。

重現用腳本：`scripts/capture_web.py`（Playwright 或 `--cdp` 模式）與 `scripts/capture_desktop.py`。

## 3. 手動驗收清單

評分者應在配備網路攝影機的機器上執行這些檢查。沒有相機時，請使用 `--demo`。

### 3.1 桌面版：啟動與版面

- [ ] `python run_desktop.py` 會以可用大小開啟無邊框工作室外殼。
- [ ] 模式切換會改變螢幕/鏡像；使用中的工具列、舞台標題與檢查器會更新。
- [ ] 左手切換會移動工具列/檢查器順序，且不會破壞舞台區。
- [ ] 最小化、最大化、拖曳與關閉均可運作；調整大小握把可調整視窗大小。
- [ ] 說明（`F1`）與新手引導可顯示並關閉；`Esc` 可關閉對話框。

### 3.2 桌面版：相機與備援

- [ ] 取得相機權限後，影像會出現；相機狀態與 FPS 會更新。
- [ ] 拒絕權限時，會顯示清楚的提示，並提供重試與模擬影像來源。
- [ ] 模擬影像來源具有標示，並可驅動真實手部骨架、繪畫與追蹤。
- [ ] 沒有相機時，滑鼠繪畫仍可運作；`Ctrl+S` 會匯出包含作品且不含介面元素的 PNG。

### 3.3 桌面版：繪畫與圖形修正

- [ ] 指向會在穩定後開始一筆；姿勢改變會結束該筆。
- [ ] 刻意畫出的實體圓形會變成乾淨的圓形；並出現辨識信心提示。
- [ ] 彎曲線/開放弧線會保持自由手繪。
- [ ] 關閉智慧圖形後，新的迴圈會保持自由手繪。
- [ ] 復原/重做會還原修正後的筆畫；清除可透過 `Ctrl+Z` 復原。
- [ ] 筆刷顏色與大小會套用至下一筆。
- [ ] 畫布 ↔ 桌面環境切換會開啟透明覆蓋層及其工具列。
- [ ] 覆蓋層可在其他應用程式上繪畫；畫布點擊可穿透；工具列的復原/清除/結束均可運作。

### 3.4 桌面版：導覽與滑鼠

- [ ] 導覽工具：一般手部移動不會觸發。
- [ ] 張開手掌 + 按住 + 依方向揮手只會觸發一次；冷卻可防止重複。
- [ ] 雙指左/右會切換上一頁/下一頁。
- [ ] 關閉系統導覽時只顯示回饋；開啟（並同意）後會送出快速鍵。
- [ ] 滑鼠工具：游標跟隨手部；捏合點擊/拖曳；雙指按住右鍵；放開會結束拖曳。
- [ ] 切換工具或模式時，絕不會讓作業系統左鍵保持按下。
- [ ] 啟用作業系統滑鼠/導覽前會出現同意對話框；取消會將該切換還原。

### 3.5 桌面版：鏡像與追蹤

- [ ] 鏡像影像會填滿舞台區；移動手部後，標註仍保持對齊。
- [ ] 標註工具會在視訊上繪畫；切換模式再切回時，鏡像筆畫仍會保留。
- [ ] 追蹤工具：圍繞物件畫圈；顯示進度環；按住；標記出現。
- [ ] 移動/緩慢旋轉物件；標記會跟隨。
- [ ] 用手短暫遮擋；標記會轉為琥珀色；復原後會轉為薄荷色。
- [ ] 將物件移出畫面；追蹤會停止並顯示「已離開相機視野」（left camera view），且不會出現失控的標記。
- [ ] 在標記上捏合可移除；清單 × 可移除；全部清除可運作。
- [ ] 至少可同時追蹤兩個不同物件（最多五個）。

### 3.6 網頁版：啟動與相機

- [ ] `python run_web.py --open` 會在 `http://127.0.0.1:8765/` 提供服務。
- [ ] 顯示歡迎對話框；相機按鈕會觸發瀏覽器權限提示。
- [ ] 拒絕權限時會產生有用的訊息，並提供示範/滑鼠路徑。
- [ ] 沒有相機時，模擬影像來源仍可運作；舞台會標示 SIMULATED。
- [ ] 相機/鏡像設定會對齊視訊、手部骨架、游標與標註。
- [ ] 授權後，裝置選擇器會列出相機。
- [ ] 讓相機持續運作至少 10 秒：視訊／舞台仍可見、WebSocket 保持連線，且沒有頁面錯誤。
- [ ] 重新載入後服務保持乾淨；不會將相機資料寫入磁碟。

### 3.7 網頁版：繪畫與控制

- [ ] 滑鼠/觸控繪畫可運作；筆畫來自伺服器狀態。
- [ ] 圓形修正可運作；修正後的圓形在視覺上是圓的。
- [ ] 復原/重做/清除可從快速動作與鍵盤執行。
- [ ] PNG 匯出會下載乾淨的作品。
- [ ] 模式/工具切換會更新畫布與檢查器。
- [ ] 手勢對應/滑桿會在工作階段內保留，且明顯影響行為。
- [ ] 說明、安全性對話框與抽屜面板可開啟/關閉；Esc 可運作。
- [ ] 在 390×844 下，工具/控制項抽屜面板可開啟並操作，且舞台區可用。
- [ ] 瀏覽器背景分頁會暫停擷取，並在返回時恢復。

### 3.8 網頁版：鏡像/追蹤與限制

- [ ] 鏡像模式與追蹤可使用瀏覽器相機影格運作。
- [ ] 迴圈選取、追蹤、遮擋復原、離開畫面與移除的行為與桌面版一致。
- [ ] 僅桌面版提供的覆蓋層/作業系統控制會顯示為不可用並附說明（而非壞掉的按鈕）。
- [ ] 惡意/不正確的設定無法從瀏覽器啟用作業系統控制。
- [ ] WebSocket 會正常關閉；若服務重新啟動，重新連線可運作。

### 3.9 無障礙與可用性

- [ ] 所有主要控制項都可透過 Tab 到達，且具有可見焦點。
- [ ] 圖示按鈕具有工具提示/無障礙名稱。

- [ ] 狀態會以文字及顏色共同傳達。
- [ ] 新手引導無需先備知識即可理解。
- [ ] 沒有相機的路徑不會走入死胡同。
- [ ] 在 200% 瀏覽器縮放 / Windows 縮放下，控制項與舞台區仍可使用（分別為網頁版/桌面版）。

## 4. 錯誤注入測試

| 情境 | 方法 | 預期結果 |
| --- | --- | --- |
| 沒有相機 | 在裝置管理員停用相機／使用沒有相機的機器 | 顯示錯誤卡片、重試、可使用示範 |
| 相機忙碌 | 開啟另一個使用相機的應用程式，然後重試 | 類似 `NotReadableError` 的訊息 |
| 缺少模型 | 將 `aircanvas/assets/hand_landmarker.task` 改名 | 顯示清楚的缺少模型提示，不當機；還原檔案 |
| 相機僅透過 Media Foundation 提供 | 在 DirectShow 失敗的情況下啟動；選擇 MSMF 後端 | `CameraPipeline` 會透過 MSMF 開啟並傳送影格，而非回報找不到相機 |
| 相機已開啟但為虛擬/空白裝置 | 使用回報已開啟但不傳送影格的虛擬相機 | 該後端嘗試會在六次讀取後遭拒，並改試下一個後端 |
| 作業系統工作階段中沒有相機 | 執行 `python scripts/diagnose_camera.py` | 回報所有後端/索引嘗試；介面提供重試、模擬影像來源與滑鼠繪畫 |
| WebSocket 中斷 | 停止網頁服務 | 顯示「OFFLINE/connecting」狀態；嘗試重新連線 |
| 網頁影格過大 | 在 WS 測試中傳送無效/過大的影格 | 送出 `error` 訊息，工作階段繼續 |
| 非本機 WS 來源 | 以另一個 Origin 連線 | 連線以代碼 1008 關閉 |
| 追蹤目標遺失 | 遮擋超過 2.4 秒 | 進入遺失狀態；保留標記供檢視 |
| 離開畫面 | 將物件完全移出畫面 | `out_of_view`，追蹤停止 |
| 滑鼠拖曳期間關閉介面 | 在捏合拖曳進行中關閉應用程式 | `release_all` 送出左鍵放開 |

## 7. 驗收標準與已知落差

**此處採用的通過標準**

- 全部 52 項自動化測試通過。
- 兩個介面都能渲染螢幕與鏡像示範，且沒有 JavaScript/Qt 例外。
- 共用核心測試證明繪畫/追蹤並未重複實作。
- 任何瀏覽器工作階段都無法觸及作業系統控制。
- 實體圓形示範會產生修正後的正圓形。
- 相機/示範失敗路徑會提供可採取行動的選項。

**已知落差**

- 沒有正式的人類參與者研究；可用性章節屬於專家啟發式評估。
- 相機在程式代理沙箱中無法存取；已用全局 Python 3.15.1 在非沙箱環境驗證。瀏覽器相機傳輸另以合成串流驗證。
- 原生作業系統滑鼠/導覽是透過程式碼審查與單元層級事件測試驗證，並未實際接管建置機器。
- 點擊穿透行為是在離屏 Qt 中於視窗旗標/生命週期層級驗證，並未針對所有 Windows 合成器驗證。
- 行動版相機權限/方向應在真實 iOS/Android 裝置上測試。
