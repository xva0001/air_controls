# 瀏覽器安全限制與功能差異

**介面：** AirCanvas Web (`http://127.0.0.1:8765`)  
**相關文件：** [介面比較](INTERFACE_COMPARISON_CN.md) · [架構](ARCHITECTURE_CN.md)

---

## 1. 為何需要本文件

AirCanvas 刻意提供兩種介面。桌面版使用原生 Qt 視窗與 Windows API。瀏覽器版則在瀏覽器的安全性沙箱中執行；這是特性，而非不便。本文件精確說明哪些行為**不可能**、**受限**或**較慢**，讓學術報告中的比較具備實證依據。

瀏覽器版並非桌面版的降級副本。它是一套完整的頁內工作室，可繪畫、進行鏡像標註與物件追蹤，同時對作業系統存取設下更安全的界線。

---

## 2. 權限與安全內容環境限制

### 2.1 相機需要安全內容環境

瀏覽器的 `navigator.mediaDevices.getUserMedia()` 僅能在**安全內容環境**（secure context）中使用：

- `http://localhost`
- `http://127.0.0.1`
- `https://...`

若透過一般 HTTP 的區域網路位址開啟網頁介面（例如 `http://192.168.1.20:8765`），通常會隱藏相機 API 或拒絕要求。AirCanvas 會偵測此情況，並在啟動面板說明相關要求。

### 2.2 相機需要明確授權

使用者必須點選 **啟用相機**（Enable camera，或歡迎畫面上的按鈕）；系統不會暗中擷取。瀏覽器接著會顯示自己的權限提示。可能結果如下：

| 瀏覽器錯誤 | 在 AirCanvas 中的意義 |
| --- | --- |
| `NotAllowedError` / `SecurityError` | 權限遭封鎖；請在網址列允許，或使用示範模式 |
| `NotFoundError` / `OverconstrainedError` | 沒有可用的相機／要求的限制條件無法滿足 |
| `NotReadableError` | 相機被其他應用程式占用 |
| `AbortError` | 擷取在開始前停止 |
| 缺少 API | 瀏覽器/環境未提供相機擷取功能 |

介面提供 **重試相機**（Retry camera）、**模擬影像來源**（Simulated feed）與 **以滑鼠繪畫**（Draw with mouse）。AirCanvas 不會儲存權限；權限由瀏覽器控制。

### 2.3 裝置標籤需要先取得授權

`enumerateDevices()` 會在取得權限前回傳裝置，但標籤通常要等使用者授權後才會顯示。相機選擇器會在授權成功後填入。使用者仍可使用預設相機，無須自行選擇。

### 2.4 權限政策（Permission-Policy）與 iframe 限制

FastAPI 服務會送出 `Permissions-Policy: camera=(self)`。若介面嵌入第三方 iframe，或由不同來源提供，相機建立可能會被嵌入頁面封鎖。AirCanvas 設計為直接開啟，不應以 iframe 嵌入。

## 3. 瀏覽器無法做到的事

### 3.1 透明桌面覆蓋層

桌面版使用 Qt 平台旗標建立全螢幕、透明、永遠置頂且可點擊穿透的視窗。網頁無法：

- 在其他應用程式之上建立頂層透明視窗；
- 在其分頁之外繪畫；
- 讓視窗對作業系統而言可點擊穿透；
- 選擇高於原生應用程式的最上層 z-order。

CSS `opacity`、`<canvas>` 與全螢幕 API 都無法脫離分頁。因此，網頁介面中的 **桌面**（Desktop）畫布按鈕會停用並說明此界線。桌面版是執行覆蓋層工作的支援途徑。

### 3.2 作業系統滑鼠控制

JavaScript 無法移動系統游標、在其他應用程式中合成點擊，或將手勢轉為原生拖曳。網頁介面提供：

- 舞台區內的**虛擬空中游標**；
- 點擊漣漪與按下狀態；
- 相同的共用滑鼠狀態機。

它無法點擊原生視窗。基於相同原因，網頁即使取得相機權限，也無法控制使用者的桌面游標。

### 3.3 系統鍵盤快速鍵

網頁在取得焦點時可以監聽按鍵，但無法將全域快速鍵注入目前聚焦的原生應用程式、傳送 `Alt+Left`，或捲動另一個應用程式。桌面原生橋接器可在明確同意後執行這些動作。網頁介面提供相同的導覽手勢辨識與回饋，但動作僅限頁內，並在文件中記錄為不可用。

### 3.4 全域快速鍵與覆蓋層結束

網頁無法註冊系統級快速鍵。鍵盤快速鍵僅限頁面。桌面版可視需求實作全域快速鍵；瀏覽器則不行。因此，網頁的繪畫與操作需要分頁保持聚焦。

### 3.5 檔案系統與靜默下載

網頁應用程式可以觸發經使用者同意的下載（PNG）。它無法靜默寫入任意資料夾，也無法讀取本機檔案。桌面版使用原生儲存對話框。

### 3.6 其他應用程式的螢幕擷取

`getDisplayMedia()` 是另一項獨立權限，可擷取螢幕，但不允許在其他應用程式中的擷取畫面上繪畫。AirCanvas 不會要求螢幕擷取；僅使用網路攝影機。

## 4. 瀏覽器支援的功能

| 功能 | 實作方式 | 備註 |
| --- | --- | --- |
| 手部追蹤 | 瀏覽器相機影格 → 本機 FastAPI → MediaPipe → 狀態 | 相機影格只傳送到本機 Python 服務 |
| 螢幕繪畫 | Canvas 2D、共用 Python 向量引擎 | 智慧圖形、復原/重做、PNG 匯出 |
| 鏡像標註 | 在即時視訊上疊加 Canvas | 座標會追蹤至內含的視訊矩形 |
| 物件選取/追蹤 | 共用 Python 迴圈偵測器 + CSRT | 相同的復原/離開畫面狀態 |
| 滑鼠/觸控繪畫 | Pointer Events → WebSocket → 共用引擎 | 透過 Pointer Events 支援觸控 |
| 虛擬游標/點擊 | Canvas 繪製的游標 + 點擊漣漪 | 無原生點擊 |
| 響應式/行動版版面 | CSS 斷點 + 抽屜面板 | 已在 390×844 驗證 |
| 鍵盤快速鍵 | 頁面 keydown 處理常式 | 瀏覽器可能保留部分快速鍵 |
| 手勢對應/調校 | DOM 控制項 → 設定 → Python | 相同的已驗證設定 |
| 新手引導/說明/安全性說明 | 無障礙 `<dialog>` 元素 | `F1`、Esc、焦點狀態 |
| PNG 匯出 | 渲染至離屏 Canvas → 下載 | 由使用者發起 |

## 6. 效能與生命週期差異

### 6.1 相機編碼

瀏覽器不會直接將原始影格暴露給 Python 服務。AirCanvas 會將目前的視訊影格繪製到隱藏的擷取用 Canvas，編碼為 JPEG（品質 0.64），再以約 12 fps 透過本機 WebSocket 傳送。這會增加：

- 瀏覽器中的 JPEG 編碼時間；
- base64/JSON 額外開銷；
- Python 中的解碼時間；
- 狀態傳遞所需的本機 WebSocket 往返。

桌面版則在行程內保留 numpy BGR 影格，完全避開這些額外開銷。

### 6.2 背景分頁

瀏覽器會節流計時器，並可能暫停背景分頁。若分頁被隱藏：

- `requestAnimationFrame` 會變慢/停止；
- 相機擷取間隔可能被節流；
- 手勢回饋可能延遲或凍結。

AirCanvas 會在 `document.hidden` 期間暫停擷取，並在分頁再次可見時恢復。桌面版沒有等效的分頁生命週期。

### 6.3 瀏覽器差異

相機限制條件、編解碼器行為、裝置標籤、自動播放政策、Canvas 反鋸齒與 CSS 支援都會因引擎而異。介面避免使用冷門 API，但仍建議使用目前的 Chrome/Edge/Firefox。Safari 可能需要額外的使用者手勢處理。

### 6.4 MediaPipe 初始化

每個瀏覽器 WebSocket 工作階段都有自己的 `InteractionSession` 與延遲建立的 `HandTracker`。模型載入期間，第一個影格可能需要約 1.2 秒。介面會顯示連線中/偵測中狀態，而不是假裝立即完成。

## 7. 本機服務安全模型

網頁應用程式是一項**本機服務**：

- 預設綁定 `127.0.0.1`（若改為 `0.0.0.0`，命令列介面會提出警告）。
- 無驗證機制；設計供本機單一使用者使用。
- WebSocket 來源必須是 localhost/127.0.0.1/::1。
- CSP 限制 script/style/connect 來源。
- 會強制執行影格大小與訊息大小限制。
- 每個瀏覽器工作階段的 `os_mouse` 與 `os_navigation` 都會強制設為 `false`。
- 影像會在記憶體中解碼與處理；不會儲存任何影格。
- 唯一的檔案寫入是應用程式程式碼/設定，並非相機資料。

若將服務暴露至 localhost 以外，請加入驗證/TLS 與隱私審查。本專案不宣稱適合公開部署。

## 8. 為何不為網頁的作業系統控制提供本機原生輔助程式？

本機 Python 服務*理論上*可以暴露作業系統控制端點，但如此一來，任何能連上該服務的本機網頁都會成為潛在的輸入注入攻擊面。本專案刻意將原生輸入注入保留在**桌面版**原生橋接器；該橋接器由使用者以應用程式形式啟動，並明確劃出瀏覽器界線。這是合理的安全取捨，且已明確記錄而非隱藏。

若未來版本加入輔助程式，應要求：

1. 明確的安裝/同意步驟；
2. 每次執行隨機產生並嵌入頁面的權杖；
3. 來源與 CSRF 檢查；
4. 可見的「原生控制已啟用」指示器與全域停止功能；
5. 相同的工具特定啟用條件與結束時釋放語意。

AirCanvas v1.0 並未為網頁版提供此輔助程式。

## 9. 使用者可見的緩解措施

| 限制 | AirCanvas 的緩解方式 |
| --- | --- |
| 相機權限遭拒 | 啟動面板說明確切錯誤；提供示範模式與滑鼠繪畫 |
| 無覆蓋層 | 「桌面覆蓋層」以鎖頭圖示與說明停用；請使用桌面版 |
| 無作業系統滑鼠 | 虛擬游標與點擊回饋；明確提示作業系統限制 |
| 無系統導覽 | 相同的手勢辨識 + 提示訊息；桌面版執行原生動作 |
| 背景節流 | 暫停擷取；使用者返回分頁後恢復 |
| 傳輸較慢 | 目標影格率、`bufferedAmount` 防護、以丟棄取代排隊 |
| 隱私疑慮 | 僅本機處理、可見的相機狀態、明確啟用、不儲存 |
| 觸控/行動版 | Pointer Events 與響應式抽屜面板 |

## 10. 總結

瀏覽器版保留了**互動模型**與**共用核心**，但未保留**作業系統層面的介面**。這項區別是介面比較的核心發現：

- 桌面版是原生工作室，可延伸至自身視窗之外。
- 網頁版是位於分頁內、可攜且更安全的工作室。
- 兩者在任何情境下都不是彼此的替代品；對同一套底層系統而言，兩者都是有效的設計。
