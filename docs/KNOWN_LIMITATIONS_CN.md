# 已知限制與未來改進

AirCanvas 是可運作的學術原型，而非正式上市產品。以下限制是觀察到或結構性的，並未隱藏。若限制源自平台界線，文件中會說明替代介面或備援方案。

---

## 1. 環境與驗證限制

| 限制 | 影響 | 目前緩解方式 |
| --- | --- | --- |
| 相機被程式代理沙箱隱藏 | 一般受限執行無法使用網路攝影機；自動對焦／USB 行為仍依環境而異 | 已用全局 Python 3.15.1 在非沙箱環境驗證（MSMF 1280×720、31.5 FPS、17.3 ms）；MediaPipe 另以真實手部照片驗證；網頁相機傳輸以合成 `MediaStream` 驗證 |
| RTMPose／YOLO 後端未內建 | 需要 `rtmlib`／`ultralytics` 與 21 特徵點 checkpoint；RTMPose-Hand 首次使用會下載模型 | 轉接器會驗證可用性並以可操作的原因失敗；MediaPipe 仍是已測試的預設。RTMPose body m/l 與官方 17 特徵點 YOLO 權重會被明確拒絕。 |
| 原生作業系統滑鼠/導覽未經實際操作 | 無法在沙箱中實際接管 Windows 桌面 | 原生橋接器經過隔離、以語意事件層級進行單元測試、預設關閉、需經同意，並在結束時釋放 |
| 點擊穿透覆蓋層僅在視窗旗標/生命週期層級驗證，未針對所有 Windows 合成器 | 多螢幕/混合 DPI/特定合成器的點擊穿透行為可能不同 | 分離的點擊穿透畫布與互動工具列；文件明確說明驗證範圍 |
| 沒有正式使用者研究 | 可學習性/滿意度主張屬於專家分析 | 以嚴重度評分進行啟發式評估，並明確標示非實證免責聲明 |
| 行動版僅在 Chromium 模擬環境驗證 | 真實 iOS/Android 的權限、方向與發熱行為未驗證 | 已實作響應式版面與觸控 Pointer Events |

## 2. 手勢辨識

- **規則式姿勢。** 可解釋且可自訂，但表現力不如訓練過的手勢分類器。模糊的手形會歸為 `unknown` 或鄰近姿勢。
- **單一作用手。** MediaPipe 可能偵測到兩隻手，但工作階段會選擇最佳候選（並依慣用手過濾）。不支援雙手互動。
- **光線/遮擋。** 極暗光線、手套、動作模糊或手部部分入鏡都會降低特徵點品質。手指直接指向相機時可能難以判定。
- **捏合定義。** 捏合需要拇指與食指靠近*且*食指伸直。若使用者以彎曲的食指捏合，可能需要不同的對應或更高的靈敏度。
- **右鍵/翻頁姿勢重疊。** 雙指同時代表右鍵與翻頁揮手。系統會依情境（工具）判定，因此使用者必須處於正確工具。
- **導覽閾值。** 刻意導覽本來就較慢；想要快速連續揮手的使用者可能會覺得待發/冷卻機制過重。設定可降低按住/冷卻時間；目前介面提供按住設定，但未提供所有冷卻值。
- **無校正。** 閾值相對於手掌比例，且大致不因使用者而異，但並非逐使用者校正。校正流程可改善無障礙性。
- **無使用者訓練手勢。** 自訂方式是對應現有姿勢，而非錄製新姿勢。

## 3. 繪畫與圖形辨識

- **長寬比容差。** 圓形辨識接受最高 1.9:1 的迴圈。在極端全景或直式長寬比下，實體畫出的圓形手勢可能無法辨識。修正後的圓形會以真正的實體圓形渲染，但偵測器本身仍在正規化影像座標中運作。
- **僅修正圓形。** 線條/矩形不會自動修正（原始規格要求圓形）。圖形模組的結構可再加入更多類型。
- **過衝/尾端。** 辨識會使用最佳尾端閉合，可容忍自然過衝，但長尾或多重迴圈可能被拒絕。
- **橡皮擦介面。** 引擎支援擦除筆畫，但兩個介面都沒有提供專用橡皮擦工具；復原/清除是主要復原路徑。
- **無壓力/速度筆寬。** 筆刷寬度在每一筆中固定；資料模型已為未來加入壓力預留空間。
- **畫布無障礙。** 自由手繪畫布本質上屬於視覺內容；筆畫幾何不會暴露給螢幕閱讀器。提供 SVG 匯出加文字描述會有所幫助。
- **向量正規化。** 螢幕與鏡像繪畫使用正規化文件座標；差異極大的舞台長寬比可能改變自由手繪（未修正）圖形外觀。修正後的圓形已妥善處理。
- **無圖層或選取變形。** 筆畫是扁平且有序的清單。無法選取既有筆畫或重新排序。

## 4. 追蹤

- **外觀模型，而非身分。** CSRT + 顏色/範本驗證可跟隨物件，但不知道物件*是什麼*。外觀相似的物件或相近背景可能干擾復原。
- **遮擋逾時。** 復原預設限制為 2.4 秒。更長時間的遮擋會進入 `lost`；標記會保留供檢視，且需要手動移除。
- **快速縮放/旋轉。** CSRT 可處理適度縮放，但快速 3D 旋轉、動作模糊或離開/重新進入畫面可能遺失物件。
- **視野（FOV）判定。** 確認離開需要反覆的邊緣失敗；緩慢盤旋在畫面邊緣的物件可能需要數個影格才能分類。這是刻意設計，以避免誤停止。
- **最大標記數。** 預設五個；更多會增加 CPU 與介面雜亂度。
- **遺失後不重新識別。** 若物件在逾時後返回，使用者必須重新圈選。
- **無語意物件偵測器。** 不會辨識「杯子」或「手機」；標籤是「Object N」。偵測/分割模型可收緊初始框並提供標籤。
- **選取時手部重疊。** 選取使用完成當下的影格；手部與物件重疊可能汙染初始外觀模型。實務上，迴圈/內縮可排除大部分手部。

## 5. 桌面版

- 以 Windows 為優先的原生橋接器與覆蓋層。其他平台可執行核心與 PySide6 介面，但不支援原生滑鼠/導覽或透明點擊穿透。
- 無邊框視窗：自訂拖曳/最小化/最大化與大小握把，但不具備完整的原生貼齊版面/邊緣調整大小行為。
- 覆蓋層依設計為點擊穿透；結束方式是浮動工具列。未實作全域緊急快速鍵。
- 覆蓋層只以主螢幕為目標；混合 DPI 多螢幕的覆蓋層位置尚未調校。
- 沒有安裝程式或程式碼簽署；安裝方式是 Python 虛擬環境。模型已隨原始碼目錄提供。
- 沒有系統匣/背景模式。
- 沒有自動更新機制。
- 相機選擇依索引/ComboBox；對 Windows 友善，但不如瀏覽器標籤具描述性。
- 自訂繪製的控制項會暴露無障礙名稱與焦點，但畫布與手部預覽不提供結構化的視覺替代方案。

## 6. 網頁版

- 沒有透明覆蓋層、作業系統滑鼠、全域快速鍵或原生檔案儲存。這些是安全界線，而非缺少處理常式。
- 相機需要 localhost/HTTPS 與權限；不支援區域網路 HTTP。
- 瀏覽器分頁節流/背景暫停可能暫停辨識。
- 相機影格會以 JPEG 編碼並透過本機服務傳輸；相較於桌面版原始影格，這會增加延遲與品質損失。
- 網頁工作階段狀態是暫時的（新的 WebSocket = 新的 `InteractionSession`）。設定/對應會在重新載入時重設。桌面版會儲存設定檔；網頁版可將安全設定儲存於 localStorage，但目前尚未實作。
- 本機 Python 服務沒有驗證；僅限迴路位址，不適合公開部署。
- 瀏覽器是自身相機影像的唯一渲染器；繪畫/標記會從狀態重新渲染，因此會有短暫的狀態往返，而非本機筆畫預覽。
- 裝置標籤需要權限；相機方向/長寬比因裝置而異。
- Safari/iOS 可能施加額外的媒體手勢/自動播放限制。

## 7. 架構、效能與可維護性

- 僅使用 CPU 的 MediaPipe 在測試機器上足以達到 30 fps，但在非常低階的硬體上，或未縮小影格而直接處理 1080p 時，可能吃力。相機輸出可設定為 720p。
- 桌面版與網頁版渲染器重複實作呈現基本元素（路徑、軌跡、骨架）。這是為了分別使用 Qt QPainter 與 Canvas 2D 的刻意設計，但視覺漂移是維護風險。共用設計權杖或渲染器規格檔案會有所幫助。
- 桌面版的單一程序處理具備執行緒安全，但只使用一個工作階段；桌面版未建立多相機/多使用者的模型。
- 網頁版為每個用戶端建立一個 MediaPipe 工作階段。多個瀏覽器分頁會使用多個模型與 CPU；沒有集區機制。
- 沒有指標/遙測；效能必須在本機觀察。
- 座標模型經過正規化，易於移植，但會使長寬比感知的圖形幾何與極端長寬比下的覆蓋層對齊更複雜。
- 原生/盡力而為清理作業周圍的錯誤處理使用廣泛例外防護；這些是刻意設計，但未在各 Windows 版本上徹底測試。

## 8. 安全性與隱私

- 預設僅限本機；若綁定至 `0.0.0.0`，則沒有驗證或 TLS。這已有文件說明，但尚未解決。
- WebSocket 來源檢查可防範最簡單的跨站連線，但遭入侵的本機頁面仍可能從允許的 localhost 來源嘗試連線。缺少作業系統控制可降低影響。
- 影格在記憶體中處理；螢幕截圖/示範包含模擬內容並具有標示。沒有錄影或雲端上傳。
- 桌面版的作業系統同意是透過對話框確認；這不是獨立的作業系統層級權限（應用程式以使用者身分執行）。以相同使用者身分執行的惡意本機程序不在處理範圍內。

## 9. 優先改進項目

### 高優先級

1. **長寬比感知的圖形辨識。** 將目前畫布/視訊的長寬比帶入繪畫/圖形層，並在擬合前轉換至實體座標空間。這可讓圓形偵測在任何長寬比下都穩健，而不只限於 1.9:1 以內。
2. **實體相機驗證套件。** 錄製一段簡短的 Y4M 手部影片，搭配瀏覽器假相機旗標與桌面版 OpenCV 後端使用；將已知手勢的驗收測試自動化。
3. **全域覆蓋層緊急退出。** 在點擊穿透覆蓋層可見時，註冊 Windows 快速鍵，並讓使用者容易發現。
4. **本機樂觀筆畫預覽與權威提交。** 在瀏覽器中立即渲染游標軌跡，再與 Python 已提交的筆畫核對；確保復原/圖形修正仍由核心擁有。
5. **儲存安全的網頁偏好設定。** 在本機儲存靈敏度/對應/主題，並在連線時送出，同時保持作業系統控制停用。

### 中優先級

6. **供網頁選用作業系統控制的原生輔助程式。** 僅在明確安裝/同意、每次執行隨機權杖、來源檢查、可見的作用中指示器與全域停止功能下提供。目前的桌面版仍是安全路徑。
7. **改良追蹤器。** 加入遺失後重新識別、更強的外觀模型、可選分割以初始化框，以及自動標記清理選項。
8. **無障礙畫布替代方案。** 提供 SVG/輪廓匯出與供螢幕閱讀器使用的文字「筆畫清單」；加入可用鍵盤導覽的筆畫選取。
9. **自訂手勢訓練器。** 為每位使用者錄製少量特徵點序列，並在規則式備援之外加入輕量分類器。
10. **雙手支援。** 獨立游標或雙手選取手勢，並提供清楚的介面回饋。

### 較長期

11. **封裝。** 已簽章的 Windows 安裝程式 / PyInstaller 套件，包含模型、自動更新與系統匣模式；以及單一指令的網頁啟動器。
12. **共用設計權杖產生**，供 Qt 與 CSS 使用，並為兩個渲染器加入視覺回歸測試。
13. **跨平台原生轉接器**，用於 macOS/Linux 輸入與覆蓋層合成器。
14. **正式可用性研究**，納入參與者（包括運動功能障礙使用者），量測任務完成率、錯誤率與 NASA-TLX。
15. **多使用者/遠端網頁模式**，具備驗證、TLS 與明確的隱私控制（並非僅限本機的產品）。
16. **更多圖形基本元素**（線條、矩形、箭頭），每種都具備保守的辨識與可安全復原的修正。

## 10. 刻意不嘗試的事項

- 錄製或上傳相機影格。
- 背景監視、人臉辨識或身分推斷。
- 未經明確同意的作業系統控制。
- 宣稱相關性追蹤器具備語意物件辨識能力。
- 以假控制項隱藏瀏覽器限制。
- 為了幾毫秒的感知速度，以 JavaScript 重新實作電腦視覺/繪畫核心。

這些選擇讓專案保持可解釋、更安全，並在學術上站得住腳。
